# 네이버 1편 리뉴얼 - evals-verification-log 01 (가독성 + 실데이터)

제목: [AI 품질검사 일지 1편] 입금 확인 AI에게 44개 문제를 냈더니 15개만 맞혔습니다

---

안녕하세요, 저스팀입니다.

저는 AI 서비스 기획자로 일하면서 "이 AI, 진짜 일을 하는가"를 숫자로 확인하는 일을 합니다.

이 시리즈 이름은 evals-verification-log, 우리말로는 AI 품질검사 일지입니다.

거창한 심사가 아닙니다. 공장에서 물건 내보내기 전에 불량품을 골라내듯, AI에게 문제지를 주고 채점하는 일입니다.

1편의 주인공은 입금 확인 엔진입니다.

[30초 요약]

입금 내역을 보고 "이거 누가 보낸 돈인지" 맞히는 프로그램에 44개 문제를 냈습니다.

결과는 15개 정답. 정답률 34.1%입니다.

깔끔한 문제는 100% 맞혔고, 현실에서 흔한 까다로운 문제는 0점이었습니다.

그래서 이 엔진은 "출시 가능"이 아니라 "기준점"으로만 보관하기로 했습니다.

[무슨 일을 시켰나]

쇼핑몰이나 소규모 가게에서 계좌이체를 받으면 이런 문제가 생깁니다.

통장에는 "홍길동843 / 35,000원 / 14시 25분"이라고만 찍힙니다.

주문서에는 "홍길동님 / 35,000원 / 코드 843 / 14시 03분 발급"이 있습니다.

이 둘을 짝지어주는 게 이번 엔진의 일입니다.

[문제지는 어떻게 만들었나]

AI 평가에서는 정답지를 golden dataset이라고 부릅니다. 저는 모범 답안지라고 부릅니다.

이번 답안지는 44개이고, 9가지 상황으로 나눠 만들었습니다.

깔끔한 일치 8개, 확실한 불일치 4개, 수수료 차감 5개, 시간 초과 5개, 코드 충돌 5개, 이름 겹침 오인 5개, 코드 위치·오타 5개, 코드 누락 5개, 대리입금 2개입니다.

만들면서 지킨 원칙 하나. 답안지는 채점할 때 절대 고치지 않습니다.

[실제 문제 예시 3개]

말로만 하면 안 와닿으니 실제 문제를 보여드립니다.

예시 1. 쉬운 문제 (cm-01)
통장: 홍길동843 / 35,000원 / 14:25
주문: 홍길동 / 35,000원 / 코드 843 / 14:03 발급
정답: 이 주문이 맞다
엔진 결과: 맞혔습니다

예시 2. 수수료 문제 (af-01)
통장: 홍길동843 / 34,990원 / 14:25
주문: 홍길동 / 35,000원 / 코드 843 / 14:03 발급
정답: 이 주문이 맞다. 10원은 이체 수수료다
엔진 결과: 틀렸습니다. 금액이 다르다며 못 찾았습니다

예시 3. 함정 문제 (ns-01)
통장: 강호동 111 / 20,000원 / 14:20
주문: 강호 / 20,000원 / 코드 111
정답: 매칭하면 안 된다. 강호동과 강호는 다른 사람이다
엔진 결과: 틀렸습니다

[어떻게 채점했나]

사람이 눈으로 봐준 게 아닙니다.

실제 엔진을 그대로 실행해서, 엔진이 고른 답과 정답이 완전히 같은지만 봤습니다.

AI에게 채점을 맡기지도 않았습니다. 그래야 "이 정도면 맞다"는 변명이 안 들어갑니다.

같은 명령을 다시 치면 같은 점수가 나오도록, 실행 명령과 파일 해시를 함께 기록했습니다.

[결과]

정확도 34.1% (44개 중 15개)

정밀도 61.1% (18번 답했는데 11번 맞음)

재현율 30.6% (찾아야 할 36개 중 11개만 찾음)

F1 40.7%

정밀도와 재현율이 어렵죠. 이렇게 보시면 됩니다.

정밀도는 "찍은 것 중 맞은 비율", 재현율은 "찾아야 할 것 중 찾은 비율"입니다.

이 엔진은 답을 잘 안 하는 편인데, 답을 해도 10번 중 4번은 틀렸습니다.

[유형별 성적표]

깔끔한 일치: 8개 중 8개 정답

확실한 불일치: 4개 중 4개 정답

수수료 차감: 5개 중 0개

코드 위치·오타: 5개 중 0개

코드 충돌: 5개 중 2개

[이 결과를 어떻게 읽어야 하나]

반 회비를 걷는 상황으로 바꿔보겠습니다.

이름과 금액이 딱 맞게 보낸 친구는 잘 찾습니다. 여기까진 만점입니다.

그런데 수수료 떼고 34,990원 보낸 친구, 한참 뒤에 보낸 친구, 메모를 "843 홍길동"처럼 거꾸로 쓴 친구, 메모를 아예 안 쓴 친구, 엄마 통장으로 보낸 친구는 못 찾습니다.

실제 입금은 뒤쪽이 훨씬 많습니다. 그래서 34.1%가 나온 겁니다.

이번 주에는 원인을 고치지 않았습니다. 고치는 주가 아니라 현재 위치를 재는 주였기 때문입니다.

[정직하게 밝히는 한계]

이 44개는 제가 만든 문제입니다. 실제 입금 데이터 분포를 대표하지 않습니다.

숫자 34.1%는 "이 엔진이 세상에서 34점"이라는 뜻이 아니라, "이 44문제에서 34점"이라는 뜻입니다.

다만 다음에 엔진을 고친 뒤 같은 44문제를 다시 내면, 올랐는지 내렸는지 정확히 비교할 수 있습니다.

기준점의 가치는 여기에 있습니다.
