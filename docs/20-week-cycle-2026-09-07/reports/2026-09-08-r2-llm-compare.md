## 1. 질문·가설

무료 Spark가 유료 Opus 5 High 대비, "모르면 비워라"가 핵심인 기록·대조 업무에서 실측으로 뒤지지 않는가?

## 2. 범위·제약

- 포함: 쏜다 입금 대조 14건, 팜로그 합성 픽스처 추출 30건, 신규 블라인드 10건의 exact match 채점
- 제외: 실제 송금, 실제 농가 음성·사진, pass^k 반복 측정, 유료/무료 티어 동일 조건 비교
- 이 리포트는 파일럿 비교이며, 모델 일반 우열 선언이 아님

## 3. 데이터·실행 조건

- 쏜다 14건: golden 원본 변경 없음. Opus 파일럿 답안의 모델명 미확정(구버전 추정), ns 세트부터 Opus 5 High

- 블라인드 10건(b01~b10): 신규 작성 텍스트. 정답은 `core.mjs` 규칙을 그대로 옮긴 Node 스크립트로 계산해 봉인
- 프롬프트·원시 답안은 session artifacts (`muse-vs-opus-*.json`, `farmlog-*.jsonl`)에 보관

- 패턴: Opus는 애매한 상황에서 격리 실패. 나쁜 값은 살리고(수량 유지·추측 기입), 좋은 값은 버림(정상 날짜 삭제). Spark는 null 규칙을 전수 준수

## 6. 실패 분류·원인 가설

- Opus의 실패는 능력 부족이 아니라 보수성 성향 차이로 관찰됨. 정보가 있으면 메우려는 방향이 기록 업무 규칙과 충돌
- Spark의 만점은 출제자 bias가 포함됨(신규 10건 출제 + 기존 정답표 사전 열람). Opus만 완전 블라인드이므로 Spark 점수는 상한 참고값
- 표본이 작고 1회 측정이라 편차 가능성을 배제할 수 없음 (ns-01은 Opus 실행 간에도 결과가 뒤집힘)

## 7. 판정

- 파일럿 범위에서는 "모르면 비워라" 과업에 한해 Spark가 Opus 5 High에 뒤지지 않음을 실측으로 확인
- 팜로그 추출기의 null-보수 규칙은 LLM 교체 시에도 유지해야 할 명세로 확정할 가치가 있음
- 모델 우열 일반화·도입 결정은 보류. pass^k와 procurement 관점의 비용 비교가 다음 단계
